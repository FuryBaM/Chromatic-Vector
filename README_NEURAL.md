# Chromatic Vector: обученный Bézier-прототип

Экспериментальная сборка `0.7.0.dev1` поверх v0.6.1. Это работающая локальная CNN с обученными весами: она получает растровый участок общей границы и предлагает две управляющие точки кубической кривой Безье. Концы кривой закреплены. Модель обучена с нуля на синтетических векторах; внешние предобученные веса и сетевые API не используются.

## Запуск

```bash
python -m pip install -e '.[test]'
python -m pytest -q
python -m chromatic_vector references/head_shoulder_crop.png head.svg \
  --mode illustrative --preset detail --contour-method neural \
  --max-side 0 --simplify 1.1 --smooth .9 --max-error 1.1 \
  --target-shapes 250 --detail-budget 100 \
  --shape-report head.json --debug-dir debug/head
```

Для эксперимента со сложными формами используйте отдельные дообученные веса. В режиме `poster` нейропредложения дополнительно проверяются по целому контуру, чтобы сохранить длинные плавные дуги.

```bash
python -m chromatic_vector references/head_shoulder_crop.png head-complex.svg \
  --mode illustrative --preset poster --contour-method neural \
  --neural-model models/bezier_patch_complex/model.onnx
```

Данные, команда обучения и проверки описаны в [карточке модели](models/bezier_patch_complex/MODEL_CARD.md).

Для экспериментального слияния мелких областей добавьте `--neural-merge`. Оно выключено по умолчанию. `--neural-optimize-steps 0` оставляет предсказанные управляющие точки без локальной доработки; допустимо 0–20 шагов, по умолчанию 5. `--neural-model path/model.onnx` выбирает другую совместимую модель; рядом обязателен `metadata.json` с контрольной суммой.

Для запуска достаточно обычных зависимостей проекта: ONNX исполняется через OpenCV DNN на CPU. PyTorch нужен только для повторного обучения. Веса поставляются в `models/bezier_patch_v1/`; копия ONNX и метаданных входит также в Python wheel. При отсутствии или повреждении весов режим выдаёт явную ошибку. Метод по умолчанию остаётся `bounded`, старые вызовы `precise` не меняются.

C++ необязателен. Для ускоренного сканирования:

```bash
cmake -S Native/ChromaticContours -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
```

## Что сделано

- Один канонический участок общей границы вычисляется для обеих соседних областей. Патчи перекрываются в пространстве изображения; фиксированная квадратная сетка в SVG не экспортируется.
- CNN получает патч 64×64: RGB, маску области и исходную границу. Дополнительный вектор из 8 чисел содержит статистику изображения и участка. На выходе — четыре координаты управляющих точек, вероятность угла и вероятность лишней границы.
- После предсказания выполняется ограниченная координатная оптимизация по исходному RGB. Это обычный численный поиск в NumPy; PyTorch и автоматическое дифференцирование при векторизации не нужны.
- Кандидат должен пройти ограничение геометрической ошибки, локальный бюджет ошибки цвета и проверку пересечений. Неподходящие предложения заменяются классической геометрией. Alpha и ручные коррекции защищены.
- Опциональное слияние учитывает уверенность модели, размер, цвет, значимость границы и ограничения alpha/коррекций. После изменения меток полностью перестраиваются зависимые данные. Отдельная проверка настоящего SVG-рендера может откатить слияние.
- JSON-отчёт содержит SHA-256 модели, исходные и доработанные параметры, причины отказов и признак `emitted` для нейросегментов, действительно оставшихся после всех проверок и подстановки примитивов.

## Измеренный результат

Сравнение с сохранёнными результатами `bounded` v0.6.1 при одинаковых настройках. RGB MAE измерена в диапазоне 0–255; F1 — совпадение краёв с допуском 1 пиксель. Меньшая MAE и больший F1 лучше.

| Голова | 241 | 5.4523 → 5.3393 | 0.8954 → 0.8982 | 453 → 453 |
| Торс | 267 | 4.4073 → 4.3047 | 0.8537 → 0.8557 | 381 → 381 |

Автоматических слияний на всех трёх фотографиях: **0**. Предложения с высокой уверенностью не прошли ограничения защищённых границ, площади или значимости. Это честный первый прототип улучшения кривых, а не законченное решение проблемы мелкой мозаики. На полном изображении F1 немного ухудшился, несмотря на улучшение MAE. По времени: около 14 с, 20 с и 324 с на этой машине; время зависит от CPU и числа областей.

## Обучение и воспроизведение

```bash
# CPU-сборка PyTorch; это дополнительная зависимость обучения
python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
python -m pip install onnx
python training/train_bezier.py --train 18000 --epochs 14
python training/export_gallery.py
python benchmarks/neural_compare.py
```

Последняя команда сравнивает уже поставленные результаты; чтобы измерить новую модель, сначала повторите векторизацию каждого исходника с настройками выше и `--neural-merge`, сохранив SVG/JSON в `artifacts/neural/v2/`. Исходники фотографий не участвуют в обучении. После переобучения для сборки wheel скопируйте `model.onnx` и `metadata.json` из `models/bezier_patch_v1/` в `chromatic_vector/assets/bezier_patch_v1/`.

18 000 обучающих, 1600 валидационных и 1600 тестовых примеров генерируются с независимыми seed. Из 14 эпох выбрана 12-я по валидационной ошибке; тестовый набор используется после выбора. Полный цикл занял около 140 с на CPU. На синтетическом тесте MAE гладкой маски: 0.00730, у прямой линии: 0.05529. Это сравнение с прямой, а не доказательство превосходства над полноценным классическим трассировщиком.

Проверено: **88 тестов** с C++, **83 теста / 5 пропусков** без него; 10 побайтовых сравнений legacy с исходным v0.5; одинаковый нейро-SVG головы с Python/C++; загрузка упакованных весов из wheel при заблокированном импорте PyTorch. Логи находятся в `artifacts/neural/`.

## Пределы прототипа

Модель обучалась на синтетических локальных кубических границах, углах и островках. Она не понимает предметы, не получает признаки полноценного глобального нейроэнкодера, не обучает порядок слоёв и не выбирает произвольное число сегментов. Между соседними участками закреплены концы, но общая непрерывность касательных G1 не гарантируется. Дополнительные слои уточнения пока используют классический bounded-фиттер. Защитные проверки сохраняют часть мелких ступенчатых контуров. Для заметного удаления мозаики требуется отдельно улучшать разбиение на области и обучать слияния на более широком наборе реальных сцен.
